# v7.0.0 架构提案：从「策略列表」到「四层管线」

> 触发背景：2026-11-13 一天内连打 4 道真实赛题，其中 3 道败在**同一种结构性缺口**上，
> 不是缺某个 gadget，而是缺「把题意表达出来」的层。
> 这份文档不是重构计划书，而是「今天每一次失败→缺哪一层」的归纳。

## 1. 今天的失败清单（事实）

| 题目 | 特征 | 原症状 | 真正缺的东西 |
|---|---|---|---|
| `7a4abf36`（0CTF welcome 型） | 724B 手写汇编、无 libc、只有 `int 0x80` | `vulns=0` → **0 次尝试** | 缺「非 libc ABI」的事实模型（syscall 包装） |
| `pwn`（PIE + 死代码 win + 全局门槛） | PIE、win 无人 call、`clearance==0xdecafbad` 才打印 | `vulns=1 wins=1` 但 **0 次尝试**；修完地址又崩在 `movaps` | 缺「目标可达性 + 上下文条件」：进 win 前要满足什么 |
| `note`（菜单式） | main 只读一个命令字符，`'w'` 才进 `write_note` | 10 个 plan 全打空，程序只回 `Bye.` | 缺**交互层**：payload 之前要先发 `w\n` |
| `bench_extra/ret2win` | `open`+`puts` 打印 flag，门槛是全局变量 | 识别不到 win；识别到后又因判定窗口 bug 判负 | 缺「判定层」：成功判据散落在各 handler 里 |

共同点：**引擎把「怎么打到」和「怎么算成功」都硬编码在 strategy 里**，
于是每遇到一个新题型，就要么加一个 if，要么在某个函数顶部 early-return（`_find_wins` 就是这么漏掉整整一类题的）。

## 2. 现状（v6.4）

```
facts.py ──► strategies.py ──► orchestrator.py ──► run.py
静态事实      候选链生成        排序/预算/留痕      收发 + 判定
```

问题：

- `Plan.sends` 是一串裸 bytes，**交互语义全丢**（哪个是菜单、哪个是长度、哪个是 payload 说不清）
- `_presets()` 是 scanf 专用硬编码；菜单、多轮泄漏、需要先读 banner 的题都没有位置放
- 成功判据有 3 份实现：`verify_shell` / `probe_flag` / `_try_pie_partial` 内部的临时判断
- 策略按固定顺序遍历 + 各自 early-return，新增一个事实很容易被别人的 `return` 挡住

## 3. 提案：四层

### L0 目标模型（Target Model）——把「题意」结构化

```python
@dataclass
class Target:
    entry:    int                  # 漏洞函数
    trigger:  list[Step]           # 到达漏洞所需的输入序列（菜单/长度/参数）
    gate:     list[Write]          # 触发前必须满足的内存状态（magic、全局变量）
    sink:     str                  # read / gets / scanf / fgets
    offset:   int                  # 到返回地址
    limit:    int                  # 单次可写字节
    bad:      bytes                # 不能出现的字节（\n / \x00 / 空白）
```

今天这 4 道题在这个模型里都能表达清楚：

| 题目 | trigger | gate |
|---|---|---|
| `note` | `[Step(line=b"w\n")]` | — |
| `pwn` | `[]` | `[Write(addr=rbp-4, val=0x7024f984)]` |
| `bench_extra/ret2win` | `[]` | `[Write(addr=clearance, val=0xdecafbad)]` |
| `7a4abf36` | `[]` | —（但 sink 是 syscall read，count 特殊） |

### L1 交互规划器（Interaction Planner）——把 sends 变成脚本

```python
# 现在
Plan(sends=[b"w\n", payload])

# 应该
Plan(script=[
    Wait(b"Write a note:"),      # 等到提示再发，别用固定 sleep
    Send(b"w\n"),
    Wait(b"Write a note:"),
    Send(payload),
])
```

收益（按重要性）：

1. **菜单题**（今天 `note`）：`cmp al,imm` 探测已能给出 `b"w\n"`，但只有规划器能保证「等提示再发」
2. **多轮题**：先泄漏、再写回，同一连接内两次 payload —— 目前完全没有位置放
3. **抗抖动**：用 `Wait(prompt)` 取代 `sleep(0.15)`，直接消掉本地/远程的时序差异（今天 `ch08` 抖过好几次）
4. **可读**：失败时能说「卡在等第二个 prompt」，而不是只留一段 tail

### L2 能力注册表（Capability Registry）——声明式选路

```python
@capability(
    requires=["pc", "bits=32", "sys_read", "writable_data"],
    forbids=["plt.system"],
    evidence="limit == off + 0x14",
)
def syscall_three_stage(t: Target, f: Facts) -> Iterable[Plan]: ...
```

要点：

- 引擎按「事实满足度」打分选策略，不再靠 `STRATEGIES` 的书写顺序
- 「早退」变成「不满足 requires 就自动不出现在候选里」，杜绝 `_find_wins` 那种一行 `return` 埋掉一整类题
- 每个能力自带 `evidence`（命中了哪条事实），失败时能打印「为什么这条没被选中」

### L3 判定层（Oracle）——把「成功」做成可插拔

```python
class Oracle(Protocol):
    def check(self, session) -> Optional[Verdict]: ...

ShellOracle()   # 发 whoami / echo PWNED_$((6*7))，看回显
FlagOracle()    # 对整个累积缓冲区做正则（★今天就踩在这）
FileOracle()    # 读取成功但内容为空 / No such file → 记 "reached, no flag"
```

三条铁律（都来自今天的 bug）：

1. **判定只能读「累积输出」**，不能只看最后一段 `recvrepeat` 的新数据
2. **「打到 win 但没拿到东西」要和「没打到」区分**：`No such file` / `lock closed` 是**链路通了**的证据
3. **判定结果要带 cause**：`flag` / `reached` / `crashed` / `no-prompt` / `gate-failed`，供 L4 用

### L4 失败归因（归因 → 下一轮选路）

把每次失败的 tail 分类，喂回 L2：

| tail 特征 | 归因 | 下一轮 |
|---|---|---|
| 只有 banner / 没有 prompt | 交互没对上 | 换 `trigger` 候选（`w` / `p` / 数字） |
| 打印了 `lock closed` / `unavailable` | gate 未过 | 换「设门槛」入口（今天已实现回溯一条） |
| 立刻崩、无输出 | 地址/对齐错 | 换 `alt` 入口 / 换 offset / 加 `ret` 滑板 |
| 有 flag 但正则没命中 | 判定 bug | 已经在 L3 修掉 |

## 4. 投入产出排序（建议）

| 优先级 | 项 | 覆盖面 | 成本 |
|---|---|---|---|
| P0 | L1 交互规划器（prompt 驱动 + 多轮） | 菜单题、多轮题、所有时序抖动 | 中 |
| P0 | L3 判定层统一（累积缓冲 + cause） | 消除假失败；今天的 bug 有 2 个在这 | 低 |
| P1 | L2 能力声明式注册 | 去掉顺序耦合与早退陷阱 | 中 |
| P1 | L0 目标模型（trigger/gate 显式化） | 是 L1/L2 的输入，做完前两项后自然浮现 | 中高 |
| P2 | L4 失败归因 | 自动换分支，减少人工看 tail | 中 |

## 5. 明确不做的事

- **不追求「零人工」**：ORW 型题（没有现成 win）本来就该人工介入，硬做只会产生假成功
- **不做加权打分黑盒**：命中率靠「事实→能力」的显式映射，不靠调参数
- **不在 strategy 里写 sleep**：时序全部交给 L1，别让每个策略自带一套时序偏好

## 6. 中间态怎么走（不推倒重来）

今天已经在做的三件事其实就是四层的雏形，继续按这个方向收敛即可：

| 已做 | 对应层 |
|---|---|
| `Facts.sys_wrappers` / `sys_read` / `sys_load` | L0（ABI 事实） |
| `Facts.gates` / `Facts.interact` / `Win.alt` | L0（gate / trigger / 对齐入口） |
| `_prelude_variants()` 前置 `w\n` | L1 的 1/10（还差 prompt 同步 + 多轮） |
| `FLAG_RE` 扫累积输出、`win reached` | L3 的雏形 |

下一步最小改动：把 `Plan.sends` 升级成 `Plan.steps`（`Send`/`Wait` 两种），
把 `execute/execute_flag/_try_*` 里三份判定合成一个 `Oracle`。
这两个改动都不需要动 facts，风险可控。
