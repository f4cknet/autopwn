# v7.3.1 — 事实层形态补全（把 Unknown 变成 Known）

> 状态：⏳ 待办（依赖 `v7.3.0` 先落地，否则改完无法验证「是修好了还是碰巧」）
> 触发：10 题样本外测试暴露的 5 个形态盲区

## 背景

`v7.3.0` 只让「不知道」被说出来；本任务逐个把 Unknown 变成 Known。
**每一项都必须能在样本外题目上验证**，不允许只为 bench 通过而改。

## 范围（5 项，按收益排序）

| # | 位置 | 改动 | 解锁 | 验收 |
|---|---|---|---|---|
| a | `model.py: _build_plt_map` | 支持 32 位 PIC 桩 `jmp dword ptr [ebx+N]`：先定位 ebx 的 GOT 基址（`call __x86.get_pc_thunk.bx` + `add ebx,imm`，或 `_GLOBAL_OFFSET_TABLE_`），再反查 `rev_got` | 题一（整类 32 位 PIE） | 题一 `plt_map` 非空，含 `printf/puts/system/__isoc99_scanf` |
| b | `facts.py: _frame_size` | 支持 `add esp, -N`（立即数按有符号处理）；遇 `and esp, 0xfffffff0` 时把对齐损耗标为未知，offset 候选按 ±[0,4,8,12] 展开而非全范围 | 题七 | `add esp,-0x80` → 128；题七 offset 候选 ≤ 4 个 |
| c | `facts.py: _find_fmt` | `:1159` 的 base 白名单加 `rsp/esp`；补 i386 `lea reg,[esp+X]; push reg` 路径 | 题七 | 题七 `fmt_buf` 非 None |
| d | `facts.py: _find_wins` | `NON_SHELL_CMD` 去掉 `"echo"`；新增 `decoy` 判定（`system` 参数是常量且不含路径 / 不含 flag 字样 → `Win.kind="decoy"`） | 题五 | 题五不再产出可成功的 flag win |
| e | `facts.py: _find_interact` | **新增**：支持 `scanf("%d")` 数字菜单（`1.Encrypt 2.Decrypt 3.Exit` 型），现有实现只认 `cmp al,imm` 字符菜单；`Facts.prompts` 对这两类也提取为空 | 题四 12cb / 题九 d8ef | 菜单导航打通后，两题用现有 `ret2libc`（有 `puts@plt`）即可尝试 |
| f | `facts.py: _audit_facts` | `offset is None` 时区分两种原因：写入目标是**全局缓冲区**（无栈溢出可言）vs 栈帧布局未知 | 题三措辞 | 报错从「帧布局未识别」改成「写入目标为全局缓冲区 0x6010c0」 |

> 原 `e`（win 剔除规则）已在 `v7.3.0` 因回归阻塞提前实施，见
> [`fix_win_filter_overreach`](../bugs/fix_win_filter_overreach.md)。
>
> 条目 `e`（数字菜单）来自 Owner 手工实证：题四/题九 的 payload 全部打在菜单提示上
> （tail 反复为 `1.Encrypt 2.Decrypt 3.Exit Input your choice! Something Wrong!`），
> 真正的堵点是菜单导航不是泄漏原语——这比「泄漏原语建模」更近、更便宜。

## 不做什么

- 不改判定口径（`oracle.py` 的 `win_executed` 态归 `v7.4.0` 之后单独评估）
- 不引入新策略

## 风险

| 风险 | 缓解 |
|---|---|
| a 项若只加正则、不建模 ebx，会把 `N` 当绝对地址 → **比现在更糟（静默解析错）** | 必须有单元断言：题一的 6 个导入名全部命中 |
| b 项对齐损耗本质不可知，可能持续差 4~12 字节 | 展开 ±12 而不是全范围，且失败原因写「对齐损耗未确定」 |
| e 项（数字菜单）若只发 `1\n` 而程序要 `1` 后无回车，会卡在 `scanf("%d")` | 两种都发（`b"1\n"` / `b"1"`），按探测到的提示串决定顺序 |

## 验收

1. bench / bench_extra / bench_sys 不低于基线
2. 题一 → 进入 ret2plt/ret2win 正常规划；题七 → 出现 fmt 计划；题三 → 出现 ret2win 计划
3. `unknowns` 中 `sink` / `offset@…` 条目数在 4 题上从 4 降到 ≤ 2

## 7. 实施记录（2026-11-14）

| 项 | 结果 |
|---|---|
| a PIC 桩 | `_build_plt_map` 用「多数票」反解 ebx → GOT 基址。题一 `plt_map` **0 → 8 个导入**（含 `__isoc99_scanf`/`system`），`vulns` 0 → 1 |
| b 帧布局 | `_frame_size` 加函数边界（遇 `ret` 停）+ `add esp,-N`/补码写法。题七 `add esp,0xffffff80` → **128**（原为 40），`offset` 从 `None` → **84**。但 `limit=20 < 84`，正确归为 `unreachable` |
| c fmt | `_find_fmt` 支持 esp 基址（换算 `fs + wordsize - disp`）；`_pushed_for_call` 补 i386 `mov [esp],reg` 传参。题七 **`fmt_buf = 88`**（原 None） |
| d 诱饵 | `system("echo …")` → `Win.kind="decoy"`，不产出 flag 计划。题五 `wins` 从 `flag@…(echo flag)` 变 **`decoy@…`**，并登记 `unknowns["win"]` |
| e 数字菜单 | 新增 `_find_numeric_menu`（`scanf("%d")` + 确实 dispatch 进含 sink 的函数）；`s_ret2libc` 接 `_prelude_variants`。题四/九 `interact={0x400b28: [b'1\n', b'2\n', b'']}` |
| f 措辞 | `_buf_is_global` 区分「全局缓冲区」与「帧布局未知」。题三 → `写入目标是全局缓冲区 0x6010c0（不存在栈溢出，需覆写全局/走逻辑分支）` |
