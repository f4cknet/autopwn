## 目标

把 a 步产出的 `Guard` / `Backfill` 变成可执行的 `Plan`，并接进 orchestrator。

## 范围

1. 载荷构造（`guard.py` 已有实现，本步启用）：
   - `build_guard_payload`：非零 dword 只写到最后一个非零字节（题一
     `A*0x34 + \x11`，+0x38 由 `.bss` 零值保证）；`scanf("%s")` 禁止空白/NUL；
     栈缓冲长度不得触达 canary/返回地址。
   - `fmt_payload`：`fmtstr_payload(idx, {global: val})`，拒绝含 `\n` 或超过
     `read_count` 的 blob。
2. `strategies.py` 三个策略（**不新增 Plan.meta 通道**，参数走 `tag`，见 C2）：
   - `s_guard_write`（tag `guard:shell|flag`）
   - `s_guard_fmt`（tag 同上；一次 `AAAA.` + `%p`×24 探针，序号拿不到不产出）
   - `s_guard_backfill`（tag `guard:backfill`；steps 为空，orchestrator 动态交互）
   - 顺序：write/fmt 在 `s_ret2win_pie` 之后、`s_ret2win` 之前；
     backfill 在 `s_ret2csu` 之后、`s_canary_fmt` 之前。
3. `orchestrator.py`：
   - `guard:backfill` → `_try_guard_backfill`（spawn、读候选 token、回填 n 字节、
     `judge_gate`）；`guard:*` 执行计划，**不重试**（输入确定，重试只会掩盖原因）。
   - 失败时把门控证据写进 `res.error`（`GATE: ...`），不改 `res.ok`。

## 验收

- 492f / 4ee0 / 71b6 → SHELL（`PWNED_42` 或 uid 行）。
- 434c → 不判 SHELL；输出含 `good job!!`，`cause == "gate_passed"`。
- 回归 13/15、5+1、4/4；盲试 = 0。

## 实施记录（实测）

| 题 | 策略 | 载荷 | 结果 |
|---|---|---|---|
| 492f | `guard_write` | 121 字节 `dead-…-beef`（约束构造） | SHELL `uid=0(root)` |
| 4ee0 | `guard_write` | 53 字节 = `A*0x34 + \x11` | SHELL `uid=0(root)` |
| 71b6 | `guard_fmt` | `%p` 探针 arg#11，`write_size=byte` 写 `0x804a02c=4` | SHELL `uid=0(root)` |
| 434c | `guard_backfill` | 读到 token `hYYurckPp1`，回填前 4 字节 | `good job!!`；`ok=False`、`cause=gate_passed`，`res.error` 以 `GATE:` 开头 |

回归：`bench` 13/15（ch07_acae / ch14_easyheap）；`bench_extra` **6 shell + 1 flag-only**
（`fmtstr1` 与 71b6 是同一二进制 md5 `eaef2247…`，被同一 `guard_fmt` 解开，高于基线 5+1）；
`bench_sys` 4/4。434c 的 41 次尝试来自其它通用策略（其真实 off=23），
守卫回填本身只尝试 1 次。

实现细节：
- tag 结构化（C2）：`guard:shell|flag`、`guard:backfill:<n>:<marker_hex>`，不新增 `Plan.meta`。
- 守卫分支**不重试**；失败原因写 `cause`/`res.error`。
- `s_guard_fmt` 只在存在 `status=="fmt"` 的守卫时做一次探针；拿不到序号不产出计划。
