# v7.3.0 — 失败可见化：事实三态 + 禁止盲猜

> 状态：🔄 进行中（文档已立项，代码未动）
> 关联：`AGENTS.md` 铁律 2 / 铁律 4；`PROGRESS.md §2`
> 触发事件：2026-11-14 用 10 道新赛题做样本外测试，**0 shell / 0 flag**；
> 461 次尝试中 231 次（50%）是盲枚举偏移，且失败的题无法说明卡在哪一层。

## 1. 背景

### 1.1 现象

`bench` 13/15 保持，但 10 道新题全灭。逐题实证后发现：

| 题 | 引擎实际行为 | 真实情况 |
|---|---|---|
| 一 4ee0 | `vulns=[]`，ret2plt 盲打 71 次 | `plt_map` 为空（32 位 PIC 桩 `jmp [ebx+N]` 未识别）→ 零 sink |
| 三 492f | `vulns=[]`，ret2win 盲打 70 次 | `main` 内有 `system` 被判 win，`facts.py:402` 连带删除 main 内的 `scanf` |
| 七 71b6 | 80 次盲打 | `_frame_size` 把 `add esp,-0x80` 算成 40（应为 128）→ 偏移不可达 |
| 十 0b5a | **0 plans / 0.1s 报 FAILED** | 三个 `read` 全被 `size_limit<=offset` 过滤，`_offsets` 返回 `[]` |

### 1.2 根因（本任务只处理第一条）

**`Facts` 的字段全是 `Optional`，`None` 同时表示「确实不存在」和「我没算出来」。**
下游无法区分两者，于是选择猜——这是「0/10」在架构层的第一因，也是后续所有形态缺陷被静默吞掉的原因。

## 2. 目标

1. 每个事实必须落在 `Known / Absent / Unknown` 三态之一，`Unknown` 携带原因。
2. `Unknown` 禁止进入盲枚举；`_offsets` 的兜底枚举删除（改为 `--allow-brute` 显式开启并计入「盲试」）。
3. 零计划 / 全部不可达时，输出 `UNRESOLVED: <原因>`，不允许空 attempts 报 `FAILED`。

## 3. 范围

### 3.1 做什么

| # | 位置 | 改动 |
|---|---|---|
| 1 | `facts.py: Facts` | 新增 `unknowns: dict[str, str]`、`unreachable: list[tuple]` |
| 2 | `facts.py: analyse` | 三处产出 Unknown：`plt_map` 为空 / 有 PLT 但无 sink 命中 / sink 命中但被 win 规则剔除 |
| 3 | `facts.py: analyse` | `_derive_offset` 返回 None 时记 `unknowns["offset@0x…"]` |
| 4 | `facts.py: analyse` | `size_limit <= offset` 不再静默丢，记入 `unreachable` |
| 5 | `strategies.py: _offsets` | 删除 `range(step, 0x120, step)` 兜底；只在 `ch.allow_brute` 时启用 |
| 6 | `orchestrator.solve` | `not res.attempts` 时填 `res.error = "UNRESOLVED: …"` |
| 7 | `cli.py` | 确认 `!! {error}` 路径生效（已有，仅核验） |
| 8 | `facts.py: analyse` | **（回归阻塞追加）** win 剔除规则从「函数入口是 win 就整批删」改为「该函数自己 `open/fopen` 才删」；新增 `_funcs_with_file_open` |

> 第 8 项原计划在 `v7.3.1`，但关掉盲猜后 `bench` 立刻从 13/15 掉到 11/15——
> `ch04_5ff0` / `ch09_cf87` 正是被这条规则误杀的（详见 [`fix_win_filter_overreach`](../bugs/fix_win_filter_overreach.md)）。
> 说明**盲枚举一直在替这个 bug 兜底**，属过拟合证据，故并入本任务。

### 3.2 不做什么

- 不修 PLT 桩形态 / 帧布局 / fmt 参数识别 / `NON_SHELL_CMD` 诱饵误判 → 归 `v7.3.1`
- 不动 `_try_ret2libc` / `_try_canary_*` 内部实现
- 不新增策略，不改判定口径
- 不做能力注册表重构（`v7.0.0` L2）——本任务是三态改造的前置，不做合并

## 4. 风险

| 风险 | 缓解 |
|---|---|
| 删兜底后 bench 掉分：说明有题原本靠盲猜命中 | **这本身是要记录的发现**。先跑 bench，若掉分则逐题登记，不因此恢复兜底 |
| `unknowns` 变成新的「什么都记」垃圾桶 | 只允许三类 key：`sink` / `offset@addr` / `vuln@addr`；CI 层不校验，靠 review |
| 报错文案过长影响阅读 | 摘要限 3 条，完整清单进 `results/*.json` |

## 5. 验收标准

1. `solve.bat bench` → 13/15；`bench_extra` → 5 shell + 1 flag-only；`bench_sys` → 4/4
2. 题十 → `UNRESOLVED: 3 个 read 全部不可达（16<40 / 1<33 / 1 个偏移未知）`，attempts = 0
3. 题七 → `UNRESOLVED: offset 未识别（帧布局）`，attempts 从 80 降到 0
4. 题三 → `UNRESOLVED: sink 命中但被 win 规则剔除`
5. 题一 → `UNRESOLVED: PLT 映射为空（桩形态未识别）`
6. 盲试占比 = 0（`--allow-brute` 未开启时）
7. **打通率不变仍然是合格**——本任务买的是「可解释性」，不是解题率
