## 1. 背景

v5 已明确转向“事实 → 交互 → 能力 → 计划 → 验证”路线；当前 runtime 仍主要依赖 `ExploitContext` 上的平铺字段，缺少显式的作用域与生命周期表达。

## 2. 目标

1. 在 `autopwn/context.py` 建立最小可用的 `FactScope` / `FactStore`
2. 显式区分 `binary / process / session / attempt`
3. 让首批 detect/runtime producer 把关键结果同步到 fact store
4. 保留旧字段兼容视图，避免一次性重写全部 strategy

- `tests/unit/test_context_facts.py`

- `tests/unit/test_orchestrator.py`

## 4. 非目标

- 不在本次引入完整 planner
- 不重写全部 strategy 为新 executor
- 不删除 `ctx.padding` / `ctx.canary` / `ctx.canary_plan`
- 不处理 `Challenge/chall`

## 5. 风险

- 如果事实层只存不接 producer，会沦为空壳
- 如果强行删除旧字段，会直接破坏当前 5/5 SUCCESS 基线
- `process` 与 `session` 的执行层消费仍需后续迭代统一，不在本次过度扩张
