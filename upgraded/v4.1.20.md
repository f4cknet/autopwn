# [v4.1.20] 治理变更：`upgraded.md` 仅保留索引，迭代详情移入 `/upgraded/`

- 状态：✅
- Owner：@Minzhi_Zhou
- 立项日期：2026-08-30
- 类型：治理变更
- 完成日期：2026-08-30
- 索引位置：[`upgraded.md §3.1`](../upgraded.md)

## 1. 背景

`upgraded.md` 已经同时承担流程规范、任务看板、需求详情、风险、验收记录等多重角色。随着 v4.1.x 继续迭代，单个任务行越来越长，导致：

- 当前任务难以快速定位
- AI Agent session 启动时阅读成本持续上升
- 任务状态索引和需求详情混在同一文件里，后续很难继续瘦身

## 2. 目标

把 `upgraded.md` 收敛为**索引与流程入口**，只保留：

- 阅读入口
- 任务索引 / 状态
- 验收基线
- 统一流程规则

每次迭代的**需求详情、范围、风险、验收记录**统一下沉到 `upgraded/vX.Y.Z.md`。

## 3. 范围

**范围**：`AGENTS.md`、`upgraded.md`、`upgraded/` 目录结构，以及当前活跃 / 新近任务的详情迁移。

**非目标**：
- 不一次性回填所有历史任务
- 不借机重写 `refactor.md` / `rebuild.md` 的历史结构
- 不改变现有任务 ID、状态机、6 关验收规则

## 4. 新规则

1. `upgraded.md` 只保留任务索引、状态、摘要、链接，不再承载整段长需求
2. 每个新任务在 `upgraded.md §3` 立项时，必须同时创建 `upgraded/vX.Y.Z.md`
3. 详情文件至少包含：背景、目标、范围、实施方向、风险、6 关验收、完成记录（如已完成）
4. AI Agent session 启动时，除读取 `upgraded.md` 外，还必须读取当前任务对应的 `upgraded/vX.Y.Z.md`
5. 历史未迁移的旧任务允许暂时保留 inline；遵循“**新建即分文件，触达即迁移**”

## 5. 迁移策略

本次先迁移：

- `v4.1.18`（已完成，便于把最新完成记录移出索引表）
- `v4.1.19`（当前待做任务，后续迭代直接在详情文件上追加）
- `v4.1.20`（本治理变更自身）

更早的历史任务保持原位，避免一次性制造超大 diff；后续当这些任务再次被引用、续做或需要复盘时，再迁移到 `/upgraded/`。

## 8. 风险

- 若把“索引化”理解成“一次性迁移全部历史任务”，会让本次治理变更 diff 失控；因此采用渐进迁移
- 若只建 `/upgraded/` 目录、不改 AGENTS session 读取规则，AI Agent 仍会漏读详情文件；因此两份治理文档必须联动
- 若未来只更新详情文件、不更新 `upgraded.md` 索引状态，会破坏任务看板的可见性；因此索引行与详情文件必须同提交同步
