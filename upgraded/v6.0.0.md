# v6.0.0 — 离线自动利用引擎（autopwn.engine）

> **状态**：✅ 完成
> **Owner**：@Minzhi_Zhou
> **触发**：2026-11-13 早间 CTF 赛前突击（Owner 明确「不依赖 AI、离线解题率 > 60%」）

## 1. 背景

v4/v5 的 orchestrator 面向「演示 + 报告」，成功判定混合了「策略跑完」与「真的拿到 shell」，
且策略实现与 pwntools 交互细节耦合很深。赛前需要一条**可度量**的离线自动化链路：
给定 15 个 pwn 二进制，自动判定保护 → 推导偏移 → 构造 payload → 交互 → 用
`whoami`/`echo PWNED_$((6*7))` 验证 shell，并输出可复核的 JSON 事实与尝试记录。

因此新增独立包 `autopwn/engine/`（v6），**不 import** v4/v5 的任何模块，避免相互污染。

## 2. 目标

- 单命令跑完一个目录的全部题目：`python -m autopwn.engine.cli bench`
- 每道题给出「成功/失败 + 采用的策略 + payload 描述 + 尝试次数 + 耗时」
- 成功判据唯一：目标进程里执行 `whoami` 或 `echo PWNED_$((6*7))` 有正确回显
- 支持本地与远程（`--host/--port`）两种目标

## 3. 范围

- 新增 `autopwn/engine/{model,facts,run,strategies,orchestrator,cli}.py`
- 新增 `docker/{Dockerfile,build.sh,solve.sh,prep_bench.sh}`（ubuntu 22.04 pwn 环境）
- 新增 `bench/`（题目归一化目录）与 `results/`（每题的 JSON 事实 + 尝试记录）
- 不改动 v4/v5 现有模块与 CLI 行为

## 4. 关键设计

| 层 | 职责 | 关键点 |
|---|---|---|
| `model` | 题目准备 | 自带 libc 时用 patchelf 改 interpreter + rpath；自建 PLT 映射（规避 pwntools 在 IBT 二进制上 +4 的问题） |
| `facts` | 静态事实 | capstone 反汇编；从 `gets/read/scanf/fgets/strcpy` 调用点回溯栈偏移；识别「函数体内 system/execve 一个 shell 字符串」的 win 函数；RWX/mmap 检测；`printf(用户缓冲)` 检测 |
| `run` | 交互与验证 | PTY 下分阶段收发（scanf 后 read 的题目必须留时间片）；成功判据 = 回显 marker 或 `uid=` |
| `strategies` | 利用策略 | ret2win / ret2system@plt / system(bss) / ret2csu / ret2libc(同进程两阶段) / ret2shellcode / i386 ret2syscall / fmtstr GOT 覆盖 |
| `orchestrator` | 排序与预算 | 按「静态事实强度」排策略，单题时间预算 + 尝试上限，逐条验证，全量留痕 |

### 4.1 偏移推导（不用 gdb）

读函数序言与调用点：

- `lea reg, [rbp - d]` → `offset = d + wordsize`
- `lea reg, [rsp + d]` → `offset = frame_size - d`
- 静态链接（无 PLT）时先从 `_start` 的 `push imm` 定位 `main`，再套用上式

推到候选后按 `[off, off±w, off±2w]` 尝试，读入长度小于偏移的直接剔除（避免几十次无效尝试）。

### 4.2 为什么 ret2libc 必须同进程

stage1 泄漏 → 回 main → stage2 必须复用同一进程的 ASLR 基址；早期版本分两次 spawn，
导致 stage2 用的 system 地址属于另一个进程空间，必然失败。v6 改为 `spawn` 一次、两次发送。

## 5. 风险

- 堆题（菜单式 tcache/fastbin）未覆盖：本批 `ch07/ch14` 未解，属于已知边界
- `read()` 长度由输入控制（负数）的题目依赖 PTY 时序，已用「分阶段 sleep + 重试一次」缓解
- 远程模式需要题目对应的 libc 文件，否则 ret2libc 基址算不准

## 6. 验收

- `bash docker/solve.sh bench` 一键跑完 15 题
- 离线成功率 **13/15 = 86.7%**，全部以「本地 whoami/id 回显」为准
- 三连跑结果一致（见 `bench/RESULTS.md`）
- 每题 `results/<name>.json` 记录保护、漏洞点、win 函数、gadget、尝试轨迹
