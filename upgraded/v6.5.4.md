# v6.5.4 新建 `ctf-pwn-local` 本地环境 Skill

- **索引位置**：`upgraded.md §2.2`
- **状态**：✅
- **Owner**：@Minzhi_Zhou
- **预估 / 实际**：0.5h / 0.5h

## 1. 背景

现有 `HANDOVER.md` / `CHEATSHEET.md` 描述的是「人读的」上手流程，但没有一份给 AI Agent 的**机器可发现**环境说明：
每次新会话都要重新确认镜像名、容器名、挂载点、工具版本与环境坑。用户要求新建 `ctf-pwn-local` Skill，
把这些事实固化成可自动加载的技能。

## 2. 目标

在仓库内提供 `.claude/skills/ctf-pwn-local/SKILL.md`，让 Agent 在处理本仓库 pwn 题目时自动获得：

- 本地 Docker 环境事实（镜像 `autopwn:pwn22`、靶机容器 `pwn-target`、挂载 `/work`）
- 工具清单与实测版本（pwntools / gdb / checksec / ROPgadget / ropper / one_gadget / seccomp-tools / patchelf / qemu）
- 自动解题与手工调试两条路径的命令速查
- Windows 宿主机环境坑（WSL bash、pyenv python、seccomp、host 网络、远程缓冲）
- 仓库纪律（临时文件、证据目录、门禁、提交）

## 3. 范围

**做：**

- 新建 `.claude/skills/ctf-pwn-local/SKILL.md`
- 内容基于**实测**：镜像内 `command -v` / `pip3 show` / 各工具 `--version`，以及 `solve.bat` / `target.bat` / `shell.bat` / `docker/serve.sh` 源码
- 在 `upgraded.md §2.2` + `PROGRESS.md §1` 登记本任务

**不做：**

- 不修改引擎代码、不改镜像、不新增依赖
- 不复制 `ctf-pwn` 的漏洞技术长文；本 Skill 只描述**本仓库本地环境**，技术细节交给 `ctf-pwn`
- 不把 Skill 放到用户级 `~/.claude/skills`（内容与仓库强绑定，应随仓库版本化）

## 4. 风险

低。Skill 是纯文档，不影响运行时；风险仅在于环境变化后内容过期。缓解：Skill 内附「如何重新探测」的命令，并在文末标注基于哪一版镜像实测。

## 5. 验收标准

- [x] `.claude/skills/ctf-pwn-local/SKILL.md` 存在，frontmatter 含 `name` / `description`
- [x] 描述的容器名、镜像名、挂载点、工具版本与实测一致
- [x] `py -3 scripts/audit/check_hygiene.py` 退出码 0
- [x] 回归不低于基线（纯文档改动，仍跑一遍三套题库）
