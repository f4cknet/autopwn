# v7.4.0a — 守卫层只读接入（guard.py + Facts + facts-only）

> 状态：✅ 已完成
> 父任务：[`v7.4.0`](./v7.4.0.md)（按评审 C1 拆为 a/b/c）
> 边界：**只读**。本步只做分析与事实登记，不产出计划、不改变任何判定与计数。

## 背景

v7.3.0 / v7.3.1 把事实层修到可用，但没有任何模块回答「输入要满足什么条件才能走到
win」。四道样本外题（题三 492f / 题一 4ee0 / 题七 71b6 / 题六 434c）的 win 都由
程序自己的判定守着，现有策略盲打或直接 `UNRESOLVED`。

评审 A0 指出：草稿 `guard.py` 把**函数入口虚拟地址**当**指令下标**用（8 处
`max(lo - 1, idx - N)`），实参解析层恒空，三题 `find_guards()` 全为 0。

## 范围

1. 重写 `autopwn/engine/guard.py`（新模块）：
   - **A0**：`_entry_index()` 统一把入口地址经 `d.by_addr` 换算成下标；所有回扫
     一律 `range(idx - 1, max(lo_i - 1, idx - 24), -1)`。
   - **A1**：沿真实控制流（BFS 最短路）走 sink → win，`call` 到同文件内函数时
     记 `("ret", entry)`；`_analyse_return_block` 递归分析判定函数的返回常量块
     （深度 1），题三 `Serialization` 的 10 个 `jne fail` 由此进入条件集。
   - **A2**：路径上所有强制分支条件的**合取**（题一两级守卫：第一级
     `(x|y)!=0` 记 oneOf，第二级 `(x^0x11)|y==0` 给出 `dword[0x34]=0x11`、
     `dword[0x38]=0`；最终以落到 win 的最后一级为准，载荷由两级共同校验）。
   - jcc 语义：`jne/jnz` 的 `want_ne = must_take`，`je/jz` 反之；只支持
     cmp/test + 相等/不等，其余记 `unknown` 并写原因。
   - 32 位 PIC ebx 只认函数内 `call __x86.get_pc_thunk.bx` + `add ebx,imm`
     的精确机制；找不到 → 不猜。
   - `find_backfills`：`strncmp(input, 运行时串, n)` + 成功分支常量串 +
     调用者打印过缓冲 → `Backfill(n=4, marker="good job!!")`。
2. `facts.py`：`Facts.guards` / `Facts.backfills` / `Facts.fmt_sites`；
   `_find_fmt` 改为 `_find_fmt_sites`（收集全部站点，保留 `fmt_buf` 语义）。
   守卫/回填分析放在 `_audit_facts` 之后，两个 try 相互独立，异常只登记 unknowns。
3. `cli.py`：`--facts-only` 打印 `guards` / `backfil` / `unknown`。

## 不做什么

- 不生成策略计划、不改 orchestrator、不改 oracle（b/c）。
- 不放松判定：gate 通过仍不是 shell。
- 不覆盖 434c 的 off=23 溢出路径（范围外，见 B3）。

## 实施记录

- A0 实测：修正前 `_arg_text -> None`；修正后题三解析出 `/bin/sh`（0x4009a7），
  四题的 Guard/Backfill 均产出（见上）。

  必须落下 → `eax != 0` → 递归到 `mov eax,1` 块 → `strlen(buf)==0x79` +
  9 个字节约束。
- 4ee0 的两级守卫在同一路径上合取；载荷构造留给 b 步。
- 71b6 的 fmt 站点按「缓冲基址+位移」匹配 `Facts.fmt_sites`（esp+0x2c ↔
  0x80485ad），不重复解析 `mov [esp],reg`（C4）。
- 全量回归首跑时 ch13_zip76c8 曾偶发失败一次（libc 泄漏抖动），单跑与二次
  全量回归均通过；基线仍为 13/15。
