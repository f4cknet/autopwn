## 1. 背景

`v5.0.2` 已把事实作用域落地，但多阶段 exploit 仍主要散落在 strategy 的顺序代码里，缺少可显式追踪的交互结构。

## 2. 目标

1. 建立最小可用的 `InteractionGraph`
2. 表达多阶段 leak / reentry / execute / verify 顺序与依赖
3. 接入至少 1 条 same-session 链路和 1 条普通 2-stage ret2libc 链路
4. 与 fact store 协同，为后续 capability / planner 迁移打底

## 3. 范围

- `tests/unit/test_detect_canary.py`
- `tests/unit/test_exp_canary.py`
- `tests/unit/test_exp_ret2libc_write.py`

## 4. 非目标

- 不在本次引入完整 capability IR
- 不重写所有 strategy 为统一 executor
- 不改 `Challenge/chall`

## 5. 风险

- 如果只做 graph 数据结构、不接真实链路，价值不足
- 如果把题目特判硬塞进 graph，会污染后续 planner 抽象
- same-session 与普通 2-stage 路线语义不同，需要通过“模板 + 运行轨迹”区分

## 6. 6 关验收

1. push 到 `main`

3. 若涉及行为变化，补对应 integration / `Challenge/` 验证
