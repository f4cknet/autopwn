# v7.1.0 prompt 驱动交互：facts 提取提示串 → 策略自动 `Wait(prompt)`

- **索引位置**：`upgraded.md §2`
- **状态**：✅
- **Owner**：@Minzhi_Zhou
- **预估 / 实际**：4h / 2.5h

## 1. 背景

v7.0.1 的 L1 交互层提供了 `Wait(needle)`，但 `facts.py` 没有输出过 prompt 字符串——
策略只能插 `Wait()`（盲等静默 1s），等不到「具体的那个提示」。这带来两个问题：

1. **每 plan 多烧 1s**：菜单题 `Send(b"w\n")` 后的 `Wait()` 是固定静默窗口；
2. **失败无法归因**：卡在哪个交互阶段只能看 tail 猜（v7.0.0 提案里 L1 的动机之一）。

现状事实源：`Facts.interact: {func_entry: [b"w\n"]}` 只有菜单字符（`_find_interact`，
facts.py:339），没有提示串。而 `note` / `repeater` 的 banner/提示都是 `puts(常量串)`，
static fact 可以稳定提取。

## 2. 目标

1. `Facts.prompts: {func_entry: [bytes]}`：该函数入口前会打印的交互提示串（如 `b"menu> "`）；
2. 策略 `_prelude_variants` 在菜单字符前产出 `Wait(prompt)` —— prompt 驱动的菜单交互；
3. 失败 attempt 的 error 带上没等到的 prompt（`WaitTimeout(needle=…)` 已有此信息）；
4. `note` / `repeater` 实打：`Wait(prompt)` 生效、基线不变。

## 3. 范围

**做：**

- `facts.py`：`_find_prompts(ch, d)`——扫 `puts/printf/write` 的**常量串实参**
  （从 `.rodata` 读出，启发式过滤：含 `:` / `?` / `!` 或以 `>` 结尾、长度 4~64、可打印）；
  归组到「下一个 call（read/gets/scanf）所属函数入口」。`Facts.prompts` 字段 + `analyse()` 赋值
- `strategies.py`：`_prelude_variants(f)` 返回 `(menu_bytes, prompt_bytes)` 对；
  `s_ret2win` / `s_ret2win_flag` 构造 `[Send(m), Wait(prompt)]`（有 prompt 用 prompt，
  没有保持 `Wait()`）
- `scripts/test/interaction_vector.py`：prompt 提取单元检查 + 真实 C 菜单程序改用 prompt 驱动
- `bench/RESULTS.md` 登记

**不做：**

- 不动 `oracle` / `interact` 运行时（`Wait` 语义已就绪）
- 不改 `_try_canary_fmt` / `_try_pie_partial` / `_try_canary_echo`（它们的交互由专用流程管理）
- 不做 prompt 与 read 缓冲的绑定校验（「这个提示对应哪个 read」属 v7.2 深化）
- 不动本地/远程时序常量（`Wait(prompt)` 的超时沿用 `_verify_timeout`）

## 4. 设计要点

| 项 | 约定 |
|---|---|
| 提取源 | `puts/printf/write` 的第一实参是**常量串地址**（lea reg,[imm] / mov reg,imm 且落在只读段） |
| 过滤 | `read_cstr` 读出后：`4 <= len <= 64`、全部可打印或含 `\n`、含 `:` / `?` / `!` / `>` 之一（交互语气的启发式）；banner（ASCII art）无标点会自然落选 |
| 归组 | 提示串的 call 距离最近的「后续 read/gets/scanf/puts(user_buf)」同帧 → 该函数入口 |
| 多 prompt | 同函数多个 prompt 按地址序列出；策略取第一个（等最外层的入口提示） |
| 兼容 | `Facts.prompts` 为空时 `_prelude_variants` 行为与 v7.0.1 完全一致（回归不变） |
| 失败归因 | `WaitTimeout` 的 msg 已带 needle；attempt error 直接透出 prompt 内容 |

## 5. 风险

| 风险 | 缓解 |
|---|---|
| 常量串误报（错误信息/菜单文字混入） | 启发式过滤 + 只取「read 前最近的那个」；`note`/`repeater`/三套回归守门 |
| prompt 与实际输出不一致（动态拼接） | 只认常量串；`Wait` 超时会如实失败，不放宽 |
| 菜单字符发送时机变化导致基线抖动 | 无 prompt 的函数保持 `Wait()`；有 prompt 才替换，逐项复刻时序 |

## 7. 实施记录

| 项 | 结果 |
|---|---|
| `Facts.prompts` | `_find_prompts(ch, f, d)`：扫 puts/printf/write 的常量串实参 → 归组到其后 25 条内最近的输入函数（read/gets/fgets/scanf）入口 |
| 提取模式 | 三种装载形态：①`lea rax,[rip+…] → mov rdi,rax`（note 型，rip 相对要算绝对地址）；②`mov edi,0x400a70` 直接进 rdi（repeater 型）；③i386 `push imm` |
| 坑 ① | capstone `detail=True` 时 `mov edi,imm` 的 `operands[0]` 是 **REG**、`operands[1]` 才是 IMM——用 `operands[0].type==X86_OP_IMM` 判永远 False（实测踩过） |
| 坑 ② | 引擎自建 `plt_map` 与 PLT 桩地址成对（+0/+4），io_out 要用 `_puts_plts` 全集匹配 |
| 过滤 | 4~64 字节 / 可打印 / 含 `: ? ! >` 之一；banner（ASCII art）与错误信息自然落选；正负例矩阵：note/repeater/ch13/ret2win ✓，canary/pwn 空 ✓ |
| 策略接入 | `_prelude_variants` 返回 `(menu, prompt)` 对；`s_ret2win`/`s_ret2win_flag` 有 prompt 用 `Wait(prompt)`、无则退化 `Wait()`；desc 带 `prompt=…` 供归因 |
| 向量 | 17/17（prompt 过滤规则纯函数断言 8 例 + 原有 15 项） |
| 回归 | note 1 attempts 取 flag；三套基线不变；repeater 本地/远程路径不受影响 |
| 遗留 | prompt→read 的绑定校验（同一函数多个 prompt 时选哪个）属 v7.2 深化；`Facts.prompts` 尚未进 `--facts-only` 输出（下次文档轮补） |
