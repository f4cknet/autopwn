# holdout/ — 样本外测量集（冻结）

> **这里的题只用于测量，不用于开发。**
> 关联任务：[`v7.5.0`](../upgraded/v7.5.0.md)
> 起点：2026-11-14，`chellenges/` 池子被实测证明已耗尽（33 题里 31 题被 `prepare()` 过），
> 改用 BUUCTF 等平台的**未做过**题目建立新测量集。

## 铁规（违反则该题作废）

1. **执行方（写引擎代码的 Agent / 人）不得读取本目录内的任何二进制、反汇编或运行结果。**
   只允许拿到验证方给出的**聚合指标 + 归因类别**（例如「2 题卡在无泄漏」「1 题是堆题」），
   不允许拿到具体题目内容。
2. **禁止为 holdout 里的任何一道题改代码。** 一旦发生，该题作废，换新题补入。
3. **跑之前先写预测**（验证方），跑完对照；事后解释不算数。
4. 本目录的题**不进 `bench/`**，不参与回归护栏。

## 目录约定

每道题一个子目录，名字自取（不用 hash，便于人工辨认）：

```
holdout/<name>/
  bin              # 必需，题目二进制（ELF）
  libc/
    libc.so.6      # 强烈建议：缺 libc 时 ret2libc 类必然失败，
                   # 那种失败算「样本不完整」，不计入引擎能力
  README.md        # 可选：来源 / 远程 host:port / 已知提示
```

也接受平铺单文件（`holdout/<name>` 直接是 ELF），但**带 libc 的题必须用子目录形态**。

## 跑法（验证方）

```bat
:: --out 指到仓库外，避免中间产物污染工作树，也避免执行方从 results/ 看到线索
solve.bat holdout --out D:\hacktools\_holdout_runs
```

## 指标（缺一不可）

| 指标 | 含义 |
|---|---|
| 打通率 | SHELL / FLAG-ONLY 占比 |
| 诊断准确率 | 失败时归因是否指向真实堵点（需人工复核） |
| 盲试占比 | 应为 **0**；非 0 说明 `--allow-brute` 被打开或兜底回退 |
| 缺 libc 单列 | 因未提供 libc 导致的失败，单独计数，不算引擎缺陷 |
