# v7.4.0c — 证据态与记账（judge_gate / win_executed / decoy）

> 状态：✅ 已完成（2026-11-14）
> 父任务：[`v7.4.0`](./v7.4.0.md)（按评审 C1 拆为 a/b/c）
> 前置：[`v7.4.0b`](./v7.4.0b.md)

## 目标

把「门控通过但没执行命令」「诱饵 win 被执行」记成**非成功证据**，并在
gate 通过时按 A3 继续找真 shell。

## 范围

1. `oracle.py` 新增（均不参与 success 记账）：
   - `judge_gate(out, marker)` → `Verdict(ok=False, kind="gate", cause="gate_passed")`
   - `judge_win_executed(out, marker)` → `Verdict(ok=False, kind="win", cause="win_executed")`
2. **A3**：守卫计划读完输出后先 `judge_shell`（累积输出，发 `id`/`PWNED_42`）；
   有 uid/marker → SHELL（正常计数）；没有才落 `gate_passed`。
3. 诱饵 win（题五）：对 `Win.kind == "decoy"` 显式打 **1 次**，结果记
   `win_executed`（已尝试、不可得分），不进 shell/flag 计数。
4. `cli.py` 计数保持 SHELL / FLAG-ONLY / FAILED 三态；`gate_passed` 显示为
   FAILED + `GATE:` 原因，shell 计数不增加。

## 验收

- 434c：`good job!!` + `cause=gate_passed`，shell 计数不变。
- 题五 decoy：attempt 记录 `win_executed`，不计 AC。
- 回归 13/15、5+1、4/4。

## 实施记录（实测）

| 项 | 落地 |
|---|---|
| `judge_gate` | `oracle.py`；`_try_guard_backfill` 的命中判断改走它（不再内联 `marker in out`） |
| `judge_win_executed` | `oracle.py`；orchestrator 的 `decoy:*` 分支专用 |
| A3 继续判 shell | `_try_guard_backfill`：gate 命中 → `verify_shell` → 有回显即 SHELL；434c 无 shell 才落 `GATE:` |
| decoy 单次尝试 | 新策略 `s_ret2win_decoy`（STRATEGIES 末位）：从 `Win.evidence` 的 `system("echo …")` 解析 marker；取同一函数**最后一个**可溢出 sink，前面的输入点先喂 `0\n` 占位；每道题只产出 1 个 Plan |
| orchestrator 分派 | `decoy:<marker_hex>`：`execute_flag` 跑计划（忽略其 ok），`judge_win_executed` 判证据，`ok` 恒 False；结尾把 `WIN: ...` 追加进 `res.error`/`res.detail` |
| CLI 计数 | 不变：`res.ok=False` → FAILED；`gate`/`win` 不计入 shell/flag-only |

实测：

| 题 | 命令 | 结果 |
|---|---|---|
| 五 | `solve.bat chellenges/fdfaa93a…` | `=> FAILED`，`!! WIN: 诱饵 win 已执行（仅回显固定串）；不记为 SHELL/FLAG`；JSON 末条 `ret2decoy` `cause=win_executed`；全题 4 次尝试（3 ret2libc + 1 decoy），`0/1 shell` |
| 六 | `solve.bat chellenges/434ced45…` | `=> FAILED`，`!! GATE: ...`；`guard_backfill` `cause=gate_passed`，`0/1 shell` |

回归：`bench` 13/15、`bench_extra` 6 shell + 1 flag-only、`bench_sys` 4/4；
`check_hygiene.py` 退出 0。

实现细节：decoy 计划不做邻近偏移枚举（`_offsets` 的 ±word 变体不用），
拿不到 `echo` 参数就不产出计划（不伪造证据）；`execute_flag` 的判定结果被丢弃，
以 `judge_win_executed` 为准——`echo flag` 不含 `flag{...}`，不能走 FLAG 记账。
