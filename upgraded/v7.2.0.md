## 1. 背景

cc7e9c60（2021 EASY PWN，stripped / 无 win / 无 /bin/sh / **scanf(%s) 坏字节封死全部
pop rdi**）与 f13e67870（cannary，canary + fmt 泄漏失败）两道新题 0 attempts 级失败。
复盘确立两条泛化路线（Owner 确认，暴力预算上限 30 分钟）：

1. **线索（hints）**：漏洞模式有限，但引擎只认「行为」（PLT 调用扫描）——
   **符号名**（vuln/getflag/flag/backdoor/win/shell）与 **.rodata 字符串**
   （flag 路径）是白给的排序证据，尤其 stripped 题的 flag 路径串是 **ORW 的前置**
   （open 打开哪个文件？路径就在 .rodata 里，不用猜）。
2. **熵暴力（entropy-brute）**：k 小（16~1000）、单次便宜、失败可检测（崩/静默可区分）
   的场景，用时间换成功率。已有 nib 爆破（v6.3.0）属此类；补 canary 逐字节、
   GOT 部分覆盖进位两类，预算参数化 `--budget`。

**边界（Owner 认可的反驳）**：暴力不替代推理——确定性堵点（fmtstr1 的 20 字节）
爆一万次也没用。hints 不做判定证据（铁律 1：成功判据不变），只做排序。

## 2. 目标

1. `Facts.hints`：符号名 + flag 路径串扫描，策略候选按 hint 插队（尝试次数下降）；
2. `ret2orw` 雏形：open(路径来自 hints) → read → write(1)，解锁 ORW 题的自动尝试；
3. `entropy-brute` 策略类：canary 逐字节 / GOT 部分覆盖进位（cc7e 型），
   `--budget` 参数化（默认 240s 不变）；
4. cc7e9c60 / cannary 实打验证（可 30 分钟预算内打穿即达标）。

## 3. 范围

**做：**

- `facts.py`：`_find_hints(ch, f)`——符号名扫 `elf.symbols`（命中 WIN_NAMES）、
  .rodata 字符串扫 flag 路径（含 `flag` + 白名单形状：`.txt` 结尾 / `/flag` / `flag\0`，
  只读段、可打印）→ `Facts.hints = {names: [...], paths: [...]}`
- `strategies.py`：`_find_wins` 排序用 hints 插队；新策略 `s_ret2orw`
  （前置：无 system/execve win、有 read/write/open PLT、hints.paths 非空、CSU 或
  pop 链可用）
- `orchestrator.py`：entropy-brute 分派（`tag=brute:*`）；cli 加 `--budget`
- `scripts/test/` 向量扩展 + `bench/RESULTS.md` 登记

**不做：**

- hints 不参与成功判定（铁律 1）；不写死路径（`/flag` 也从二进制里扫）
- 不做 libc-database / ORW 的 seccomp 深化；不动 oracle/interact
- 不改变三套回归的分母与预期

## 4. 设计要点

| 项 | 约定 |
|---|---|
| 符号 hint | `elf.symbols` 名字含 win 关键词（`getflag/flag/backdoor/win/shell/vuln`）且落在 .text |
| 路径 hint | `read_cstr` 扫 .rodata：正则 `[\w./]*flag[\w./]*`（大小写不敏感），白名单形状过滤，4~64 字节 |
| 排序 | `_find_wins` 产出的 Win 带 `evidence`；hints 命中的函数入口排序提前（`STRATEGIES` 顺序不动） |
| ORW | 用 csu（rdi/rsi/rdx 三参）或 pop 链拼 `open(path,0) → read(fd,buf,0x60) → write(1,buf,0x60)`；路径字节流写 bss（csu 的 read 调用） |
| brute-canary | fork 服务器 canary 跨连接不变：逐字节 0~255 试，崩=错、存活=对；7 字节 ≤1785 连接 |
| brute-got | 部分覆盖 1~2 字节（4~16 bit 熵），枚举 + 真实执行判定 |
| 预算 | `--budget` 秒（默认 240 不变）；brute 策略在 budget 内自由分配 attempts |
| cause | brute 失败 cause=`brute_exhausted`，不放宽判据 |

## 5. 风险

| 风险 | 缓解 |
|---|---|
| hints 误报（`flag` 撞无关文案） | 只做排序证据；路径白名单形状；evidence 记 `name|str` 复盘可辨 |
| ORW 无 seccomp 时 execve 也可用 | 先试 system/execve 路径，ORW 是兜底；libc 泄漏后 ret2libc 优先 |
| brute 单题吃满预算 | budget 内每类 brute 独立计时；全局 deadline 优先 |
| 基线抖动 | hints 只改排序不改判定；三套回归守门 |

## 7. 实施记录

| 项 | 结果 |
|---|---|
| **cannary 打穿**（本地+远程）：`=> SHELL canary_fmt canary=…-> win 0x401262`，5 个真 bug 修复——①probe 长度按 size_limit 截断（184B>32B 被截）；②probe 改位置参数 `%N$p`（arg0=6+canary_off/word）；③`_canary_candidates` 删 `v%0x1000==0` 页对齐误杀与 `2^56` 上界误杀（15/16 的 canary 被排）；④`_try_canary_fmt` 有 backdoor 时直接 ret 到 win；⑤该分支原限定仅本地，远程落回需 pop_rdi 的 ret2libc 必败——放宽为本地/远程通吃。远程真取 `CTF2{891eecf6-…}` |
| **ae3f24d3 打穿**（远程）：`ret2libc_write`（csu 泄漏型）没接远程 libc 识别——三处补齐：①策略远程双泄 write+read GOT；②**csu 双块连用链错位修复**（第二块不能重复 p64(A)，pop 槽会把它当值消费）；③`_parse_leaks` 支持 write 型连续 16 字节双段解析。远程 `remote-libc[libc6_2.23]` 自动识别，真取 `CTF2{163031b6-…}` |
| **cc7e9c60 判定能力边界**：scanf(%s) 坏字节封死唯一 pop rdi；fmt 泄漏走 printf@plt→resolver 的 xsave 区需 rsp≥0x601110，bss 段尾 0x6010b0 物理不可达；brute 不适用（20-bit 熵）。GDB 逐级实证，教训入 PROGRESS §4 |
| hints 排序 | `_find_wins` hints 插队（符号名 getflag/backdoor/shell/win/flag 落 .text）——只做排序证据（铁律 1） |
| verify_shell | 远程 TLS 空读容忍（首个空读不再立即 break） |
