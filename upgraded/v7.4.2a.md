## 1. 缺口 A：数字菜单判据

### 现状

`facts._find_numeric_menu` 只认一条路径：`scanf("%d")` 所在函数**直接 call** 进
`vuln_funcs`（含 sink 的函数）。样本外题的分派不满足（例如 `read + atoi`、
helper 读选择 + main 分派、`switch` 跳表），于是 `interact` 为空，
payload 被当成菜单输入。

### 设计（判据只新增，不放松到「任何输入调用」）

结果仍合并进 `f.interact`（key = 菜单函数入口），`strategies._prelude_variants`
按值遍历，策略侧零改动。两条路径：

1. **旧路径原样保留**：函数体内（入口起 400 条）存在对 `vuln_funcs` 的直接 `call`，
   且该函数有 `scanf("%d")` → 候选 `[b"1\n", b"2\n", b""]`。
2. **新路径**：同一函数同时满足三项证据，缺一不可：
   - **输入调用**：`read / gets / fgets / scanf / __isoc99_scanf / getchar / getline`
     之一（覆盖 `read + atoi` 型菜单；`atoi` 不要求单独识别）；
   - **编号横幅**：`.rodata / .data.rel.ro / .data` 的常量串（先按 `\x00`、再按 `\n`
     切分）中有 ≥2 个不同编号的菜单项。匹配 `^\s*[\[(]?([1-9])[.)\]:]\s*`，
     标签必须含字母或非 ASCII 字节（排除 `1.0`、`1.2.3` 版本串）；
     `"1.Encrypt\n2.Decrypt\n3.Exit"` 这类单串多行菜单也能命中；
   - **分派证据**（输入调用之后、同一函数、60 条内）：≥2 个不同的小常数比较
     （`cmp/sub` 立即数 ∈ [1..9]），**或**出现计算跳转 `jmp [reg*W+disp]`（switch 跳表）。
   - 候选由横幅编号导出：`b"1\n"..b"k\n"`，跳过标签含 exit/quit/bye 的编号，
     最多 4 个，末尾补 `b""`。

**负例保护**：无编号横幅不触发（`ch03_58a4` 这类长度输入不受影响）；
`b""` 空前缀始终保留，误报只多一次尝试，不会封死原路径。

### 边界

- 不解析 `atoi`/`strtol` 的数据流；分派证据负责证明「输入值被拿去分派」。
- 横幅与分派在同一函数内才算；跨函数菜单（main 分派到 helper 的输入）不在本轮。
- `chellenges/` 在 holdout 建立期间暂停主动运行，真样本命中由验证方下轮盲测确认。

## 2. 缺陷 D：shell 路径合法性

现状 `if "/bin/sh" in text or text.strip().endswith("sh")` 会把 `fish`、`push`、
`/bbbb…?/sh` 判成 shell win。改为纯函数 `_win_kind(text) -> Optional[str]`：

```python
t = text.strip()
shell = t in ("sh", "/bin/sh", "/bin//sh", "/usr/bin/sh")
if not shell and "/" in t:
    head, _sep, base = t.rpartition("/")
    shell = base == "sh" and bool(head) and os.path.isdir(head)
```

其余分支顺序不变：`FILE_READ_CMD` → flag，`NON_SHELL_CMD` → decoy，否则丢弃
（**不往假地址跳**）。

| 输入 | 旧 | 新 |
|---|---|---|
| `/bin/sh`、`/bin//sh`、`/usr/bin/sh`、`sh` | shell | shell |
| `fish`、`push` | shell（误判） | 丢弃 / 按命令词判 decoy |
| `C:\foo\sh`、`/bbbb…?/sh`（目录不存在） | shell（误判） | 丢弃 |
| `system("bash")`、`system("/bin/sh -c …")` | shell / shell | **不判 shell**（边界，按验证方口径收紧） |

## 4. 实施记录（2026-11-14）

### 改动

- `facts._find_numeric_menu`：旧路径原样保留；新增第二路径（输入调用 + 编号横幅 +
  分派证据），候选由横幅编号导出，末尾保留 `b""`。
- `facts._win_kind`：新增纯函数；`_find_wins` 改用它；`Win.arg_addr` 记录实参串地址。
- `facts._scanf_addrs` / `_input_call_addrs`：**改为从 `ch.plt_map` 收全部同名地址**。
  合成向量暴露的真实 bug：现代 gcc 产物里 `.plt` 与 `.plt.sec` 会同时映射同一符号
  （如 `__isoc99_scanf` 同时在 `0x401060`、`0x401064`），调用点只落在其中一个，
  而 `ch.plt(name)` 只返回其中一个 → 旧判据在该形态下永远看不到输入调用。
  这个修复对旧路径同样生效（不是只为新路径）。
- `cli.py`：`--facts-only` 增打 `interac:` / `global:` 两行，便于冒烟比对。
