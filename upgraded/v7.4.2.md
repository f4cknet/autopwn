### 实施中发现（值得单列）

1. **PLT 别名**：现代 gcc 产物里 `.plt` 与 `.plt.sec` 同时映射同一符号，
   调用点只落在其中一个，`ch.plt(name)` 只返回其中一个 → 旧 `scanf("%d")` 判据
   在该形态下永远看不到输入调用。已改为从 `ch.plt_map` 收全部同名地址
   （`_scanf_addrs` / `_input_call_addrs`）。这很可能就是缺口 A 样本的直接原因之一。
2. **x64 全局地址**：`_buf_is_global` 旧实现只认 `mov reg, imm` / `push imm`，
   漏掉 `lea reg, [rip+disp]`；缺口 B 的 64 位形态需要它，已补。
3. **32 位打包**：`s_global_write_win` 原用 `ch.p64`，已改为按 `ch.wordsize` 打包，
   否则 32 位题会写错槽位。

### v7.4.2c2（⏳ 只登记）

验证方复核目标静态题为 `static=True / bits=32 / binsh=None`。C1 只修归因与事实提取，
**不承诺打通**。C2 内容：

1. 静态 i386 的 ROP gadget 发现（静态 glibc 的 `pop eax/ebx/ecx/edx; ret` 与 `int 0x80`）；
2. 没有 `/bin/sh` 常量时，先用溢出把 `"/bin/sh\0"` 写进 `.bss`，再回 main 触发第二次溢出，
   `execve(bss, 0, 0)`；
3. 仅在 C1 的 `f.vulns` / `main` / writer 都具备时启用；与既有 `s_ret2syscall_write` 的差别是
   后者依赖 `ch.plt`/`f.binsh` 已存在的形态，C2 要覆盖「静态符号直呼 + 无 binsh」的组合。

> 本轮 C1 若让 `_static_vulns` 产出 `f.vulns`，既有 `s_ret2syscall_write` 允许自然尝试
> （它有 `writer/main/bss` 输入时不算新代码），但不为它新增代码、不承诺成功。
