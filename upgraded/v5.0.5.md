# [v5.0.5] 最小 planner 入口
- 状态：✅
- Owner：@Minzhi_Zhou
- 立项日期：2026-08-31
- 索引位置：[`upgraded.md §3.1`](../upgraded.md)

## 1. 背景

`v5.0.2` 已落在 facts，`v5.0.3` 已落在 interaction graph，`v5.0.4` 已落在 capability。当前 runtime 仍直接由 `exp.registry` 的候选排序驱动，尚未把“候选 strategy + capability 链”收束为显式的 plan 对象，因此还没有真正进入 `v5_architecture.md §3` 中的 Planner 层。

## 2. 目标

1. 建立最小可用的 planner 入口
2. 把 `ranked_candidates()` 产出的候选与 capability 链收束为显式 `ExploitPlan`
3. 让 orchestrator 在进入 strategy 执行前能看到当前 plan 与 capability 顺序
4. 保持 legacy strategy 执行链不变，不破坏当前 5/5 SUCCESS 基线

## 3. 范围

- `upgraded.md`
- `upgraded/v5.0.5.md`
- `autopwn/planner.py`
- `autopwn/orchestrator/strategy.py`
- `tests/unit/test_planner.py`
- `tests/unit/test_orchestrator.py`

## 4. 非目标

- 不在本次统一改写 verifier 执行层
- 不在本次引入完整搜索 / 回溯 / 成本模型
- 不重写 `exp.registry` 的 hard gate / hint 评分逻辑
- 不改 `Challenge/chall`

## 5. 风险

- 如果 planner 只是重命名日志而不落 plan 对象，会丧失建模价值
- 如果 planner 绕开现有 hard gate，会破坏当前 strategy 选择基线
- 如果把 strategy 名或题目名写死到 planner，会污染后续泛化
